Remote PC Flutter v1.0.3 — 安全渗透审计报告

审计日期: 2026-06-09 审计人: Senior Developer (白帽渗透) 项目版本: 1.0.3+3 攻击面: 12 个文件 / 5 个网络端点 / 3 个原生桥接

Executive Summary

本次审计模拟真实黑客攻击链，对 Remote PC Flutter v1.0.3 进行全面渗透测试。共发现 2 个严重、3 个高危、4 个中危、3 个低危 漏洞，以及 5 项加固建议。最严重的漏洞可导致攻击者在 LAN 内无需认证直接关机目标设备。

漏洞详情

ID严重级别分类漏洞描述攻击向量修复建议
RPC-001 CRITICAL 加密 硬编码 AES 密钥
LicenseManager._aesKey 使用固定字符串 'RemotePC-2026-Secret-Key-32Byte!!' 派生密钥。APK/IPA 反编译后密钥直接暴露。		 攻击者反编译后可解密所有激活码、伪造授权 使用 Android Keystore / iOS Keychain / Windows DPAPI 存储密钥，运行时派生而非硬编码
RPC-002 CRITICAL 认证 Token 生成使用伪随机
_generateToken() 使用 DateTime.now().microsecondsSinceEpoch % 256，这是时间戳取模，可预测性极高。		 攻击者可根据时间戳推算 Token 值，暴力破解仅需 ~2^16 次尝试 替换为 Random.secure() 或 dart:math Random.secure() 生成 32 字节真随机
RPC-003 HIGH 网络 HTTP 服务绑定 0.0.0.0
HttpServer.bind(InternetAddress.anyIPv4, port) 对所有网卡开放，同 LAN 内任何设备均可访问控制端点。		 同 LAN 攻击者可直接访问 /ping /heartbeat 等端点，获取 SAFE_MODE 状态 默认绑定 InternetAddress.loopbackIPv4，仅本地访问；跨网络通过 WebRTC DataChannel 中转
RPC-004 HIGH 网络 UDP 发现协议无认证
UDP 广播使用固定 magic header REMOTE_PC_V3，无签名校验。攻击者可伪造设备广播，注入恶意设备到列表。		 MITM 攻击：伪造设备引导主控端连接到攻击者控制的 HTTP 服务 广播消息加入 HMAC-SHA256 签名，密钥通过带外通道交换
RPC-005 HIGH 认证 /auth-token 端点 localhost 检查可绕过
仅检查 clientIp == '127.0.0.1'，未考虑 DNS 重绑定攻击（ attacker.com 解析到 127.0.0.1）。		 恶意网页通过 DNS 重绑定可读取 Token，进而执行关机等指令 添加 Origin / Referer 检查；或使用自定义 HTTP Header 要求而非仅 IP 校验
RPC-006 MEDIUM 代码 激活码校验算法过于简单
verifyActivationCode 仅检查格式 + 首字符 ASCII 和 mod 37 == 0。碰撞概率高（约 2.7%），且算法公开于源码中。		 攻击者可批量生成有效激活码，绕过授权 使用服务端在线验证 + 非对称签名；本地校验采用 HMAC-SHA256 而非简单取模
RPC-007 MEDIUM 加密 DynamicFirewall 验证算法可逆
挑战验证规则为 sum(unicode_codepoints) % 997，算法与 Dart/Java/Swift/C++ 四端完全一致且公开。攻击者拿到 challenge 后可直接计算 response。		 防破解核心逻辑可被完全绕过，防火墙形同虚设 原生层使用设备绑定密钥进行 HMAC 签名验证，而非简单数学运算
RPC-008 MEDIUM 桥接 MethodChannel 可被 Hook 拦截
Flutter MethodChannel 消息未加密，可通过 Frida/Xposed 等 Hook 框架拦截和篡改 MethodChannel 通信。		 攻击者可 Hook isBeingDebugged 返回 false，绕过调试检测 关键校验逻辑完全在原生层闭环，不通过 MethodChannel 返回中间结果；增加完整性校验
RPC-009 MEDIUM 代码 DynamicFirewall 心跳 50% 概率跳过验证
heartbeatCheck() 中 _rng.nextBool() 决定是否验证，50% 概率直接返回 true。		 攻击者有 50% 机会通过心跳检测，大幅降低防护有效性 每次心跳必须验证；或改为 90%+ 验证概率
RPC-010 LOW 代码 Windows 完整性校验过于简单
VerifySystemIntegrity() 仅检查 kernel32.dll 和 ntdll.dll 是否加载，以及 VMware 注册表键——这几乎永远返回 true。		 完整性校验基本无防护效果 添加 EXE 签名校验、代码段 hash 校验、关键 DLL 完整性校验
RPC-011 LOW 网络 WebRTC TURN 凭证硬编码
openrelay.metered.ca 的 TURN 凭证 openrelayproject/openrelayproject 硬编码在源码中。		 凭证为公共免费服务，可被滥用导致服务限流或不可用 使用自建 TURN 服务器或通过 API 动态获取临时凭证
RPC-012 LOW 桥接 原生自毁不彻底
macOS 自毁未清除 FlutterSecureStorage (Keychain) 中 remote_pc_activation 条目。Android 自毁使用反射调用 clearApplicationUserData，部分设备不支持。		 自毁后仍可能残留部分数据 macOS 补充 Keychain 清除；Android 增加 fallback 手动清除逻辑

SAFE_MODE 防护评估

防护有效场景

✓SAFE_MODE=1 环境变量 → 拒绝关机/重启/锁屏执行
✓x-test-mode 请求头 → 拦截但记录日志，不执行
✓未授权请求 → 返回 403 Forbidden
✓审计日志记录所有危险指令尝试

防护绕过场景

✗Token 可预测（RPC-002）→ 攻击者获取有效 Token 后，SAFE_MODE OFF 时可直接执行
✗HTTP 绑定 0.0.0.0（RPC-003）→ 同 LAN 设备可直接请求 /safe-mode 查询状态
△SAFE_MODE 默认 OFF → 首次启动无保护，需用户手动开启
△无 SAFE_MODE 强制锁定 → 运行时可随时关闭，无二次验证

网络攻击面分析

LAN 模式攻击面

1
UDP 4567 — 广播发现，无认证，可伪造
2
HTTP 9998 — 控制端点，Token 认证但生成可预测
3
HTTP 9990 — 篡改告警服务（LicenseManager._reportTamperToMaster），仅 localhost

跨网络模式攻击面

1
WebSocket 信令 — 未验证信令服务器身份，WSS 证书未校验
2
WebRTC DataChannel — DTLS 加密（由 WebRTC 协议栈保证），相对安全
3
STUN/TURN — 公共 TURN 凭证可被滥用

代码级漏洞演示

RPC-002: Token 可预测性验证

// 当前实现 (http_server.dart:73-78) String _generateToken() { final rand = List<int>.generate( 32, (_) => DateTime.now().microsecondsSinceEpoch % 256); return base64Encode(rand); } // 攻击：如果知道服务器启动时间，可以精确计算 Token // 32 个字节，每个字节 = timestamp_us % 256 // 如果启动时间误差在 1 秒内，暴力空间仅 10^6 ≈ 2^20 // 实际更糟：连续字节的值高度相关 // 修复方案 String _generateToken() { final rand = Random.secure(); final bytes = List<int>.generate(32, (_) => rand.nextInt(256)); return base64Encode(bytes); }

RPC-001: 硬编码密钥提取

// license_manager.dart:16 static final _aesKey = _deriveKey('RemotePC-2026-Secret-Key-32Byte!!'); // 反编译 APK 后： // $ jadx -d output app-release.apk // $ grep -r "RemotePC-2026" output/ // → 直接获取密钥明文 // → 可解密所有激活码、伪造授权数据 // 修复方案 // Android: 使用 Android Keystore // iOS: 使用 Keychain + Secure Enclave // Windows: 使用 DPAPI CryptProtectData // macOS: 使用 Security.framework SecKeyCreateRandomKey

RPC-003: HTTP 0.0.0.0 绑定风险

// http_server.dart:64 _server = await HttpServer.bind(InternetAddress.anyIPv4, port); // 攻击：同 LAN 内任何设备可直接访问 // $ curl http://192.168.1.100:9998/ping // → {"status":"alive"} // $ curl http://192.168.1.100:9998/safe-mode // → {"safeMode":false,...} // 无需认证即可查看状态！ // 修复方案 _server = await HttpServer.bind(InternetAddress.loopbackIPv4, port);

防御加固建议 (Beyond Fix)

◆证书固定 (Certificate Pinning) — 信令服务器和 TURN 服务器启用 SSL Pinning
◆速率限制 — HTTP 端点添加请求频率限制，防暴力破解 Token
◆CORS 策略 — HTTP 响应添加 CORS Header，阻止浏览器跨域请求
◆
运行时完整性 — 定期校验 APK/EXE 签名哈希，异常则自毁
◆SAFE_MODE 默认 ON — 首次启动默认开启，需明确操作才能关闭
