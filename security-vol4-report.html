Vol.4 漏洞发现

CRITICAL ATK-W06 ✓ 已修复
设备指纹绕过漏洞
DeviceWhitelist.isAllowed() 中，如果请求不包含 fingerprint 参数，指纹校验直接跳过。 攻击者只需知道合法 deviceId（可从网络流量嗅探），不发送 x-device-fingerprint 头即可绕过白名单。
1 嗅探 LAN 流量获取合法 deviceId
2 发送请求时 不包含 x-device-fingerprint 头
3 isAllowed() 跳过指纹校验 → 直接放行
❌ 修复前
// fingerprint 为 null → 跳过
if (fingerprint != null && d.containsKey(kFingerprint)) {
  return d[kFingerprint] == fingerprint;
}
return true; // ← 直接放行！
✅ 修复后
// 有指纹 → 必须提供且匹配
if (storedFingerprint.isEmpty) return true;
if (fingerprint == null || fingerprint.isEmpty)
  return false; // ← 必须提供指纹
return _constantTimeEqual(
  fingerprint, storedFingerprint);
修复方案
① DeviceWhitelist.isAllowed() 中白名单有指纹时，fingerprint 必填且使用常量时间比较
② _checkDangerousAction() 中 x-device-fingerprint 为必填头
HIGH ATK-W07 ✓ 已修复
Auth Token 日志泄露
服务器启动时 print 输出 auth token 前 8 字符。32 字节 Base64 编码约 44 字符，前 8 字符将暴力搜索空间从 2^256 降至约 2^48。 如果攻击者能访问进程输出（如 Docker logs），可大幅加速暴力破解。
❌ 修复前
print('[HTTPS] Server started on port $port'
  '(auth token: ${_authToken!.substring(0, 8)}...)');
✅ 修复后
print('[HTTPS] Server started on port $port'
  '(TLS: $useTls)');
// 注意：不再输出 auth token 任何部分
修复方案
完全移除 token 输出，只记录端口号和 TLS 状态
HIGH ATK-W08 ✓ 已修复
请求体大小无限制 — OOM 攻击
/pair 和 /unpair 端点直接读取整个请求体，无大小限制。攻击者可发送超大 JSON（如 1GB）， 导致服务端内存耗尽崩溃（OOM Kill），实现拒绝服务攻击。
修复方案
① 新增 _readBodySafe() 方法：检查 Content-Length + 实际读取大小，超过 10KB 拒绝
② /pair 输入字段长度验证：deviceId ≤ 64, name ≤ 128, fingerprint ≤ 256
③ /unpair 输入字段长度验证：deviceId ≤ 64
MEDIUM ATK-W09 ✓ 已修复
速率限制无递增 + 无全局频率限制
速率限制固定 60 秒封禁，攻击者每分钟可试 3 次密码。按此速率，一天可尝试约 4,320 次。 另外无全局请求频率限制，攻击者可高频发送请求造成服务压力。
修复方案
① 递增封禁：第 1 次 60s → 第 2 次 5min → 第 3 次 30min → 第 4 次+ 1h
② 全局频率限制：同一 IP 每秒最多 10 个请求（100ms 最小间隔）
③ RateEntry 新增 blockCount 字段追踪累计封禁次数
MEDIUM ATK-W10 ✓ 已修复
错误信息泄露 + 输入未消毒 + 时序侧信道
三合一漏洞：① /pair 错误响应包含异常堆栈信息，泄露内部实现细节； ② 审计日志未对输入做截断，可注入超长字符串； ③ _constantTimeEqual 长度不同时提前返回，泄露 Token 长度信息。
修复方案
① 错误响应不再包含异常信息（如 "Invalid pairing data" 而非 "Invalid pairing data: FormatException"）
② 审计日志 action 截断至 64 字符，clientIp 截断至 45 字符
③ _constantTimeEqual 长度不同时仍遍历完整长度，消除时序侧信道
MEDIUM ATK-W11 ✓ 已修复
WebSocket 信令明文传输
SignalingClient 使用 ws:// 连接信令服务器，SDP offer/answer 和 ICE candidate 全部明文传输。 中间人可截获 WebRTC 连接建立信息，甚至注入伪造 SDP 实现中间人攻击。
修复方案
新增 _ensureSecureUrl()：非 localhost 的 ws:// 自动升级为 wss://。 本地开发环境（localhost/127.0.0.1）保持 ws://，生产环境强制 wss://。

Vol.3 自检发现

Vol.4 开始前对 Vol.3 修复进行自检，发现 ATK-W01（白名单绕过）修复不完整：

自检发现：Vol.3 修了 deviceId 必填，但 fingerprint 仍是可选的。 攻击者知道合法 deviceId 后，不发送 x-device-fingerprint 头即可绕过指纹校验。 这是典型的链式漏洞——修了 A 绕过点，攻击转移到 B 绕过点。
教训：安全修复必须验证整个攻击链，而不能只修单个检查点。 白名单机制的两个维度（deviceId + fingerprint）都必须强制校验。
