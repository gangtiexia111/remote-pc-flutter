🔴 HIGH 级漏洞 (4)

V7-01 HIGH /unpair 缺少 POST 强制 — CSRF 可解绑所有设备
攻击向量: 浏览器访问 <img src="http://localhost:9998/unpair"> 即可通过 CSRF 解绑设备。
影响: 无需认证即可通过 GET 请求解绑已配对设备。
文件: http_server.dart
添加 POST 方法强制检查，使用 _respondMethodNotAllowed(req) 统一 405 响应。
V7-02 HIGH 空指纹绕过白名单 — isAllowed isEmpty→true
攻击向量: device_whitelist.dart 中 if (storedFingerprint.isEmpty) return true — 如果白名单中设备的指纹为空，任何提供匹配 deviceId 的请求都直接通过。
影响: 攻击者只需获取 deviceId 即可绕过指纹验证。
文件: device_whitelist.dart
修改 isAllowed 逻辑：请求必须提供非空 fingerprint，storedFingerprint 为空时仍验证 deviceId 匹配 + 请求提供了非空指纹。
V7-03 HIGH getHardwareFingerprint() 失败返回空串 — 白名单绕过
攻击向量: NativeSecurityBridge.getHardwareFingerprint() 在 MethodChannel 失败时返回空字符串 ''，配合 V7-02 空指纹绕过逻辑，攻击者可在任何平台伪造空指纹通过白名单。
影响: 原生桥接失败的平台上，所有白名单指纹验证可被绕过。
文件: native_security_bridge.dart
失败时返回 sentinel 值 __FINGERPRINT_UNAVAILABLE__ 而非空串，不会与白名单空指纹检查冲突。
V7-04 HIGH HMAC/AES 密钥复用 — 加密密钥兼做签名密钥
攻击向量: verifyActivationCode() 使用 AES 加密密钥作为 HMAC-SHA256 的 secret key。违反密码学原则：加密和认证密钥应独立。
影响: 如果 AES 密钥泄露，攻击者不仅能解密，还能伪造激活码签名。
文件: license_manager.dart
通过 HKDF-SHA256 从 AES 密钥派生独立的 HMAC 密钥（info="RemotePC-HMAC-KEY-V1"），两个密钥分别存储在 FlutterSecureStorage。

🟠 MEDIUM 级漏洞 (8)

V7-05 /pair 405 返回纯文本而非 JSON
_handlePairRequest 对非 POST 请求返回纯文本 "Method Not Allowed"，与 V6-02 其他端点的 JSON 格式不一致。纯文本响应可能被某些客户端错误解析。
文件: http_server.dart
统一使用 _respondMethodNotAllowed(req) 返回 JSON 格式的 405 响应。
V7-06 _isTestMode() 生产环境可用 — 暴露安全状态
x-test-mode 和 x-safe-mode 请求头可在生产环境绕过 SAFE_MODE 查询的认证，暴露 SAFE_MODE 状态给未认证方。
文件: http_server.dart
使用 Dart assert + kDebugMode 编译时常量门控，生产构建中 _isTestMode() 始终返回 false。
V7-07 _clearActivation() 不删 AES/HMAC 密钥 — 自毁后密钥残留
selfDestruct() → _clearActivation() 删除了激活记录和 deviceId，但 AES 密钥和 HMAC 密钥仍保留在 FlutterSecureStorage 中。攻击者可利用残留密钥伪造激活码。
文件: license_manager.dart
_clearActivation() 中同时删除 _aesKeyAlias 和 _hmacKeyAlias，确保自毁彻底。
V7-08 _saveActivation() 用 SharedPreferences — 激活状态可篡改
激活状态保存在 SharedPreferences（明文 XML/JSON 文件），任何有文件访问权限的应用/用户可篡改激活状态。
文件: license_manager.dart
迁移到 FlutterSecureStorage（Keychain/Keystore/DPAPI）。Linux 无 libsecret 时降级到 SharedPreferences 并警告。
V7-09 DataChannel 无消息速率限制 — 泛洪攻击
WebRTC DataChannel 没有消息速率限制，恶意 peer 可通过泛洪消息耗尽 CPU 资源。
文件: webrtc_connection_service.dart
添加 30 msg/s 速率限制器，超限消息直接丢弃并记录日志。
V7-10 sendCommand() 无出站校验 — 可发被禁指令
DataChannel 的入站消息有白名单过滤，但出站 sendCommand() 没有校验。应用层代码可直接发送 shutdown 等被禁指令。
文件: webrtc_connection_service.dart
sendCommand() 添加与 _handleDataChannelMessage 相同的 blockedCommands + allowedCommands 双重校验。
V7-11 roomId 无输入验证 — 信令注入
SignalingClient 的 createRoom/joinRoom/leaveRoom 对 roomId 没有长度和字符限制，恶意 roomId 可用于信令服务器注入攻击。
文件: signaling_client.dart
添加正则验证 ^[a-zA-Z0-9_-]{1,64}$，不符合的 roomId 直接拒绝。
V7-12 isBeingDebugged() fail-open — 检测失败等于无检测
NativeSecurityBridge.isBeingDebugged() 在 MethodChannel 调用失败时返回 false（fail-open），意味着调试检测在原生桥接故障时完全失效。
文件: native_security_bridge.dart
改为 fail-closed：调用失败时返回 true（认为正在被调试），与 verifySystemIntegrity() 一致。

🟣 自检修复 (1)

V7-自检-01 空 Host 头绕过 DNS Rebinding 检查
_isLocalHostHeader() 中 if (hostHeader.isEmpty) return true — 空的 Host 头被当作本地地址处理，绕过了 DNS rebinding 防护的第二层。
文件: http_server.dart
改为 if (hostHeader.isEmpty) return false — 空 Host 头视为非本地，强制走认证路径。
V7-自检扫描了 14 个源文件中以下模式的一致性：

✅ SecureStorageValidator — 5 文件覆盖 (certificate_manager, device_whitelist, license_manager ×2, dynamic_firewall)

✅ 空 Host 头 — 修复后统一为 false
✅ fail-closed 策略 — isBeingDebugged + verifySystemIntegrity 一致
