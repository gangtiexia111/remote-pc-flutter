🔧 关键修复详解

V5-02 CRITICAL — 运行时证书生成

核心问题：私钥 key.pem 打包在 assets 中，任何能解包 APK/EXE 的人都能提取。

// 修复前：私钥打包在 assets 中（可提取） finalCert = (await rootBundle.load('assets/certs/cert.pem')).buffer.asUint8List(); finalKey = (await rootBundle.load('assets/certs/key.pem')).buffer.asUint8List(); // ❌ 私钥暴露
// 修复后：运行时生成临时证书，私钥存在 FlutterSecureStorage if (await _certManager.loadOrGenerate()) { finalCert = utf8.encode(_certManager.certPem!); finalKey = utf8.encode(_certManager.keyPem!); // ✅ 私钥在安全存储 }

CertificateManager 安全策略：

  • 优先从 FlutterSecureStorage 加载已生成证书
  • 如果不存在，调用 openssl 生成新的 RSA-2048 自签名证书
  • 私钥保存到 FlutterSecureStorage（各平台加密存储）
  • 临时文件中的私钥用随机数据覆写后删除
  • 如果 openssl 不可用，降级到 HTTP（而非使用不安全的固定私钥）
  • pubspec.yaml 只打包 cert.pem（公共证书），不打包 key.pem

V5-03 HIGH — 并发互斥锁

// 修复前：多个 await 可能同时修改 _devices Future addDevice({...}) async { _devices.add({...}); // ← 另一个请求可能同时修改！ await _save(); // ← 覆盖前一个请求的修改！ }
// 修复后：Completer 互斥锁 Future addDevice({...}) async { return _withLock(() async { _devices.add({...}); // ✅ 互斥保护 await _save(); }); }

V5-06 — 严格 Host 头解析

// 修复前：startsWith 可被 127.0.0.1.evil.com 绕过 final isLocalHost = host.startsWith('127.0.0.1') || host.startsWith('localhost');
// 修复后：正确解析 host:port，精确匹配 bool _isLocalHostHeader(String hostHeader) { String hostname; if (hostHeader.startsWith('[')) { // IPv6: [::1]:port hostname = hostHeader.substring(1, hostHeader.indexOf(']')); } else { // IPv4: host:port final colonIndex = hostHeader.lastIndexOf(':'); hostname = colonIndex > 0 ? hostHeader.substring(0, colonIndex) : hostHeader; } const localHostnames = {'127.0.0.1', 'localhost', '::1', '0:0:0:0:0:0:0:1'}; return localHostnames.contains(hostname.toLowerCase()); }

⚠️ 已知限制（非代码可修）

  • WebRTC 应用层加密：WebRTC 自带 DTLS-SRTP 加密，但未加额外应用层 E2E 加密（需 Signal Protocol 级别改造）
  • 信令服务器证书固定：信令服务器地址动态，无法预知证书（可加 TOFU 机制，待 UI 配合）
  • 物理访问：攻击者物理接触设备时，无法防止内存提取 Token（需 mlock 级别保护，Dart 不支持）
  • 本地恶意软件：管理员权限的恶意软件可绕过所有防护（操作系统的根本限制）
  • 依赖项审计：pointycastle/cryptography 等依赖的 CVE 需手动检查
